# Treatment guide comparison

The Treatments collection has a native `Treatment Guide — wheel` component below the existing guide. The old guide remains available for comparison. The native component owns the heading, CMS introduction, chapter labels, typography, dividers and source content. The current iteration is an explicitly requested temporary patch with two stacked versions: cream and charcoal finger-pad rings. The second version copies the existing bound DOM, rewrites its IDs/references, removes the repeated heading and supplies independent basic tab navigation. Designer and the initial unenhanced page retain the original thin-orbit layout until this trial is approved for native migration.

The treatment name, introduction, chapter titles and full chapter bodies use existing CMS bindings. Five short introductions are shared component properties: the Treatment collection is at its 60-field limit. No collection fields or treatment content were changed. The title remains an editable component property. No content is fetched or replaced by JavaScript.

## Ownership and loading

- `src/runtime/treatment-guide-loader.js` is a small presence/consent gate. It prepares the wheel near the section and replays an initial drag after preparation. Native Webflow tabs and native details provide navigation and full chapter content when an enhancement fails.
- `src/treatment-guide/wheel.js` owns pointer/keyboard motion. The pad has five edge-to-edge background-coloured dividing lines, starting at twelve o'clock. A small marker rests midway along each line; chapter labels are hidden only in the enhanced state. Ring arrows and card arrows share selection. Unwrapped angles cross twelve o'clock without jumping; release momentum feeds an angular spring with radial guard rails inside the pad. The shared motion profile controls timing, and work stops when settled, offscreen, hidden or destroyed. The SVG viewport owns pad touch-action; its empty centre and corners remain outside the hit area. Direct gestures, arrows, keyboard selection and Learn more invoke the existing slider focus lifetime to move the site bars away.
- `src/treatment-guide/card.js` creates one temporary preview per version from its bound panes. Pagination, arrow controls and the usual black Learn more button retain their DOM nodes and positions across all five chapters. Current and incoming pagination values have explicit full-slot geometry for `TDBNativeTicker`. Titles slide horizontally; blurbs use the shared fade timing. All five text rows reserve their maximum height. Learn more always opens the current chapter.
- `src/treatment-guide/drawer.js` is prepared on Learn more intent. It reuses USP styles, shared drawer, ticker, Swiper, reading-state and controls. The header uses equal text styles and equal-width columns around a truly centred rule. A fixed 14rem introduction area follows the review drawer's icon/rule/excerpt geometry. Its text fades while the chapter body moves. The same `TDBNativeTicker` now accepts an optional artwork renderer for the diamond, existing thumbprint, lotus, quotation marks and barn-window assets. The default text renderer remains unchanged. Artwork is warmed only on drawer intent. Chapter changes move the originating wheel beneath the drawer; each comparison has its own state.
- `tdb-treatment-guide.css` contains the temporary scoped ring/card patch and established drawer differences. It loads near the guide, before wheel mounting; no guide layout is added to shared initial CSS. If the enhancement fails, native tabs/details remain visible. If the drawer fails after the preview mounts, the selected native full body is revealed and focused.
- The shared drawer's default focus behavior is unchanged. The guide returns focus to the persistent Learn more control (or the active native chapter's control in fallback mode).

## Validation and limits

Automated Chrome checks cover desktop, 390px and 320px layouts, all five tabs, stable preview height, native content when both guide modules are blocked, keyboard selection, spring intermediate frames, touch dragging beyond the orbit, colour interpolation, drawer selection, focus return, close, inner scrolling and phone landscape. Physical iPhone Safari remains untested. Desktop backgrounds are inert while the modal is open; the wheel continues to reflect drawer selection visually.

The 981-test suite includes seven guide tests and a new artwork-renderer interruption test. Browser checks cover both variants, persistent controls, actual ticker frames, all four arrow controls, marker rest positions, edge-to-edge lines, chrome focus, title travel, blurb fades, mouse/touch gestures, drawer targets, matching header typography, centred rule, all five icons, fixed intro geometry, focus return and native fallback. Build artifacts and release inventory must be checked together. The existing unrelated `src/smile-gallery/feed.js` formatting warning remains outside this change. Changed source files pass formatting checks.

The native five full bodies count toward initial page HTML, including closed details. The temporary old/new comparison intentionally duplicates that content. Drawer copies and Swiper loop copies are deferred until intent. The wheel adds shared motion/ticker requests only when not already loaded; drawer dependencies are likewise deduplicated by `TDBModules`. File/gzip estimates are asset budgets, not measured TBT or browser transfer totals.

The click-wheel patch adds one small card controller to the existing wheel bundle and loads the scoped stylesheet near the section. Exact raw/gzip sizes and source lists are recorded in `config/build-artifacts.json`; existing shared downloads reduce the cold path. Native page CSS and HTML are separate Webflow output. No new global startup request or homepage guide request is introduced.

From the Designer perspective, bindings and resting layout remain editable. From the visitor perspective, content and controls remain useful through loading failure. From the runtime perspective, physics and drawer construction have separate lifecycles and gates. From the release perspective, all four install references move to one immutable commit, with a staging-only publish.

## Rollback

Restore the privately saved site head/footer blocks and publish staging only. Hide the comparison component in Designer to remove the new native guide; the original guide and collection schema remain intact. Do not commit private HTML, CMS exports or full custom-code backups. Production publication is outside this review.
