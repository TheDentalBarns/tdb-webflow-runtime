# Shared contact and journey planner

The shared Contact us definition owns the contact links, native journey form, reserved result space and map frame. Home has no instance and gains no DOM. Six decorative icon embeds and wrappers have been removed; pseudo-element masks reuse canonical Webflow SVG Assets (including the existing footer Instagram/Facebook artwork). The mobile link now has a working `tel:+447488893573` destination.

The former Elfsight embed contained only its widget ID. It is replaced by an in-page Google Maps and Routes enhancement. Native GET form submission and the separate directions link remain useful without JavaScript. Google code is conditional on proximity and functional consent. A deliberate submit requests one traffic-aware driving route with only path, duration and distance. Origin text is kept only in the form/current memory; this module writes no storage or analytics. Failed requests retain the external directions link. Consent withdrawal removes map/route DOM and invalidates pending results; it cannot recall already transmitted requests.

## Departure and arrival choices

The native footer uses the calculator’s existing colour hierarchy: charcoal/neutral-darker background, cream text, sand labels and darker cream help text. Its bottom padding is 2rem. Existing alternate secondary buttons remain; shared external control states give them cream hover/press feedback using the central timing. The connector cannot uniquely target their duplicate-named alternate combo style, so moving the light border from the existing external rule into Designer is pending an authenticated Designer session. No extra button class or replacement element was added. It owns three groups: departure, road preference and arrival guidance. It spans both columns on desktop and stacks beneath the map at 991px and below. Icons follow their labels; At the barns uses the navigation barn asset. The native checkbox follows “Prefer to avoid major roads?”. Its unchecked state is explicitly white with appearance:none; the checked state reuses the canonical review tick as a charcoal mask. Forced-colour mode restores the browser checkbox. The update button has the shared distance/journey mask after its label. A pseudo-element avoids another native icon element; the usual loading spinner retains its separate pseudo-element.

Leaving now displays the actual current UK time as HH:mm, with no added hour. The existing proximity observer also watches this input; one minute-boundary timeout runs only while nearby and visible, and is cleared on mode change, consent withdrawal or teardown. A no-JS placeholder of --:-- avoids inventing a static current time. Leaving later enables the existing reserved input as `datetime-local`. It suggests one hour ahead only when first switching modes and preserves partial edits and a previously entered value. UK wall time is interpreted with Europe/London independently of the device timezone. Past times, the missing spring hour and ambiguous autumn hour are rejected rather than silently shifted. Requests use `TRAFFIC_AWARE`, optional `departureTime` and `routeModifiers.avoidHighways`. Avoidance is a preference, not a guarantee. Traffic-aware routing has its applicable Google API charge. Origin, departure and avoidance all participate in the 60-second deduplication key and consent/first-submit replay. Changing origin invalidates an outstanding result. Departure and avoidance edits remain draft preferences: the currently submitted route and estimate remain visible, including when a previous request is in flight, until Update journey is submitted. Google Maps URLs do not support carrying these site departure/avoidance preferences, so the separate external directions button does not promise that handoff.

Arrive with confidence reuses the existing Map and business pin. Parking and both walking approaches are stored on the shared native root as `data-tdb-journey-parking`, `data-tdb-journey-path-1` and `data-tdb-journey-path-2`. Coordinates follow the owner's annotated satellite screenshots; paths are schematic walking guidance, not surveyed accessible routes. Both now stop at the building edges instead of joining the business marker. Straight segments follow the outside and courtyard approaches. Both routes share one vertical approach, with the lower branch running directly from the split to the building. The upper endpoint is moved south to follow the wall. Each separate final segment carries the shared walking mask and the native root label “Under 1 min”, confirmed by the owner. This supersedes the incorrect distance-based two-minute approximation; no Google walking request is made. Each path uses a cream 4px stroke over an 8px charcoal stroke to remain visible against satellite imagery. Both provider strokes are removed together. The canonical asset is `6ae2124223c07a12ee6449f5_tdb-walking.svg`. The parking label and walking chips use the established dark translucent pop-out surface, white artwork and 20px blur. They add only transient Google overlay content, not Designer elements or inline SVGs.

I have an appointment reuses the existing date/time input, with independent saved values for later departure and appointment modes. Appointment mode starts blank and requires a valid future UK date/time. The existing result area is reserved at 12rem and the note uses pre-line spacing, so leave-by information does not push the directions button down. The target arrival is 15 minutes before the appointment. Driving Routes has no arrival-time mode: the module makes at most two traffic-aware requests, estimates departure from the initial duration, then checks traffic at that departure. It retains the earlier conservative departure, rounds down to the minute and labels the result as an estimate. If the buffer is no longer possible, it says to leave now and warns about the buffer. No arrivalTime is sent for DRIVING. Appointment requests can incur two routing API charges. Draft edits, stale-response cancellation, consent replay and deduplication remain intact.

Returning to my journey restores the retained route without another Google request. Update journey now centers the map at every breakpoint, including when the cached route is reused, and restores it from arrival mode. Both arrival and return actions center the portrait map on mobile before camera presentation. A bounded native animation timeline uses the existing central `TDBMotionProfile.vertical` duration and travel easing. Pointer/wheel/keyboard input cancels the page scroll; hidden documents, new requests and consent teardown release its animation and frame. Reduced motion uses immediate centering. Arrival camera fitting uses the same shared camera owner and a maximum zoom of 19. All arrival lines/markers are removed on return or teardown. There is no second map, perpetual loop, map-type switcher, custom Designer code or IX2 binding.
