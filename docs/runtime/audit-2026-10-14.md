# JavaScript collection audit — 14 October 2026

## Conclusion

The newer runtime has useful shared infrastructure and substantially better feature ownership. The collection is **not yet one clean final release**: active pages still mix modern homepage modules, old page controllers, multiple immutable versions and a separate attribution repository. Consolidating source/build/release ownership is worthwhile. Combining every feature into a large global script would defeat the presence, consent and proximity gates already doing useful work.

This branch supplies a reviewable foundation: a complete captured reference catalog, recovered active sources, consistent formatting, 57 manifest-built outputs, fully minified production builds, reproducible checks, and two narrow runtime reliability fixes. It does not change the website, CSS pins or the paused footer/TBT experiment.

## Scope and evidence

- Read all **62 Webflow page/template custom-code blocks** plus global settings.
- Inspected published HTML references on **28 non-draft static pages** and **all 152 sitemap URLs** on staging; no page-fetch errors.
- Captured **64 immutable artifacts across 55 repository paths**, including two attribution versions, direct scripts, conditional controllers, shared dependencies and CMS-embedded scripts. The catalog includes draft-only references separately through their consumers/configuration labels.
- Reviewed the current source/build tree alongside the pinned code. The captured inventory is a static reference/dependency audit, not a claim that every asset downloads on every page or that every conditional path was exercised in a browser.
- Production domains were not crawled or changed. The sitemap does not prove coverage of every historical/unlisted CMS URL. Generated Webflow/jQuery/IX2 and third-party SDKs are dependency boundaries, not code maintained in this repository.

See [the exact pins and consumers](../../config/runtime-inventory-2026-10-14.json), [per-artifact catalog](module-catalog.md), [source recovery provenance](../../config/source-provenance.json), and [ownership/bundle decisions](module-map.md).

## What is already working well

- `TDBModules` deduplicates resolved URLs and can validate required exports before declaring readiness.
- `TDBScrollLock` uses independent owner tokens. This is worth extending rather than replacing with per-overlay body locking.
- The newer review request client shares in-flight requests without one cancelled consumer aborting another; it guards pagination loops and retains data/imported assets rather than fetched page documents.
- Availability already has a compact public-feed path, validated cache entries, a shared per-channel request and suspended refresh scheduling when hidden/unobserved.
- Native carousel controllers share Swiper, motion and ticker behavior; visibility, progress and initial-entry handling have regression coverage.
- Vimeo/analytics/Brevo have distinct permission owners. Several newer loaders correctly recheck state after asynchronous loads and retain native fallbacks.

## Candidate implementation

The source tree now includes previously missing active calculator, archive, motion, slider-focus, tooltip, gallery-page, legacy IG/review and template owners. Two existing source files (review CMS and availability) were restored from their actual currently pinned versions, rather than treating the older branch copies as deployment truth. Where only a shipped artifact was available in that tree, the provenance record says so; formatting cannot recover original variable names from an already-minified artifact.

There are **57 canonical build targets**, plus the separate pinned Swiper build. Readable assembled bundles are generated under `build/readable/`; checked-in `src/` is consistently formatted. Historical dist artifacts remain listed outside the manifest instead of being silently rebuilt from mismatched modern sources. Existing source changes that were intended to be formatting-only were normalized with compression/mangling disabled: **93 files had no semantic text change under that normalization**.

The runtime reports version **1.4.2** for the two reliability fixes. Other feature APIs and their semantic versions are retained. The collection itself is a candidate, not a blanket claim that all features now share one approved release.

## Verification and remaining release gate

- **311 passing tests, zero failures, two fixture-dependent skips** (Brevo public bootstrap and published Webflow Tram integration).
- All **64 captured CDN URLs returned content matching the recorded Git blobs** (eight initial timeouts succeeded on one retry). This is a delivery check, not a latency benchmark.
- Deterministic rebuild check and formatting check passed; all readable bundle targets assembled successfully.
- Swiper build retained its existing security patch/license markers and passed vendor checks plus carousel tests.
- Tests exercise minified outputs where applicable; updated older fixtures to the current definition-only Five Senses entry, shared scroll lock, hosted review artwork and current CSS/loader ownership. Original behavioral checks were retained, with text-equality checks replaced by export/behavior checks where minification made the old assertion invalid.
- Real iPhone Safari/Chrome, Webflow integration, legacy-route markup, GPU/audio and visual/motion checks remain before deployment. No site publish or performance experiment was performed.

The recommended order is: review the two runtime fixes, validate the minification/source-recovery candidate on staging, migrate old IG/review consumers, then simplify the release manifest and reconcile main. The [release procedure](releasing.md) makes the exact rollback and browser gates explicit.

## Build references

Minification policy follows [Terser compression options](https://terser.org/docs/options/) and its [property-mangling cautions](https://terser.org/docs/cli-usage/). Private identifier mangling and additional safe passes are enabled; cross-file property names and unsafe transformations are not.
